Agent Skills Deep Dive

October 22, 2026 · 2:30pm – 5:30pm PT (3 hours)
Online workshop led by Marcelo Lewin

An agent skill is a reusable package of instructions, knowledge, resources, and tools that teaches an AI agent how to perform a specific kind of work. Here is the shape of the workshop, and the seven ideas it is built around.

If you use an AI assistant for real work, every conversation starts from zero. You re-explain your brand voice, your research process, your review checklist, the format your team expects. The answer comes back good enough, the window closes, and the knowledge goes with it.

A skill is how you stop doing that. You capture the process once and give your agent a repeatable way to apply it when the situation calls for it. Your expertise stops living only in conversations and starts becoming reusable infrastructure.

That framing is where this workshop starts.

How the Three Hours Run

  1. Fundamentals. What a skill is, how agents discover and load one, and progressive disclosure.
  2. The design decisions. Instructions versus reference, judgment versus determinism, structure, and composition.
  3. The lifecycle. Testing, debugging, versioning, and evolving a skill as your process changes.
  4. Hands-on. Build a skill from your own work, test it against real scenarios, and improve where it breaks.

That is the shape. Here is what each part actually covers.

A Good Skill Is More Than a Prompt

A prompt is a single instruction you happened to phrase well. A skill has structure. It can contain your process and standards, reference supporting documents and templates, include scripts for steps that need to be deterministic, and be tested, versioned, improved, and shared. Once a process is a file instead of a habit, it behaves like software: you can find where it breaks, fix that place, and keep the fix.

Progressive Disclosure

The first instinct is to write everything down. Every rule, every edge case, every example, in one file. It feels thorough and it makes the agent worse, because the three things that matter are now buried under forty that rarely do. A well-built skill announces what it is and when to use it, loads its core instructions when the situation calls for it, and reaches for deeper material only when a step needs it.

Instructions Versus Reference Material

Designing for progressive disclosure forces a decision you cannot avoid, and we spend real time on it.

If the agent needs it every time the skill runs, it is an instruction. If it needs it occasionally, for a specific question or a specific case, it is reference material and belongs in a file the skill can open when asked.

Judgment Versus Determinism

Some steps genuinely need judgment. Does this sound like us? Is this research thin? Is this the right recommendation for this client? Models are good at those, and rigid rules make them worse. Other steps have exactly one correct answer every time: renaming files to a convention, validating a structure, counting something, transforming a format. Those should be scripts, not instructions, because an instruction is a suggestion and a script is a guarantee. Knowing which is which is most of the craft.

Structure and Composition

Skills grow. The ones that stay reliable grow outward rather than downward: files organized so the agent can find what it needs without reading everything, and separate skills that call each other instead of one monolith that tries to do research, drafting, and formatting in a single set of instructions. A skill that does one thing well is easier to test, and far easier to fix.

Testing and Debugging

This is the part almost nobody does, and it is the difference between a skill you trust and one you babysit. You run the skill against real scenarios, watch where the behavior goes soft, and trace it back to the instruction that was ambiguous or the step that should have been deterministic. Then you cover the lifecycle around that: organizing the files, using version control, documenting changes, and evolving the skill as your process changes.

And Then You Build One

Most of the session is hands-on. You bring a task from your own work that you find yourself explaining to an AI assistant over and over, and we build it into a skill step by step with Claude (or your favorite AI agent that supports skills), test it against real scenarios, find where it breaks down, and improve it.

No programming experience is required. The emphasis is not on becoming a developer. It is on learning how to turn your expertise into a system an AI agent can reliably use. You leave with a working skill, a framework for designing better ones, and a method for turning more of your knowledge, processes, and standards into reusable capabilities.

  • No coding experience needed.
  • This workshop is for domain experts, knowledge workers, and product thinkers who want their AI agent to work the way they do.
  • Helpful, but not required: you’ve used an AI assistant like Claude or ChatGPT for real work and have a sense of where it falls short.
What should I set up before the workshop?
  • An AI agent that supports skills, installed and working.
